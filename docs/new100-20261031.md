# Additional 100 Official Pairs

User authorization: run 100 previously unstarted official combinations to obtain
more diagnostic cases. This is not a repeat of the completed lite100 study.
Each selected pair gets one paid attempt; no automatic model retries or paid
judge. No new monetary ceiling was specified. The existing 71/100 scoreboard
is not replaced by this batch. Failed/incomplete runs remain in the denominator.

Before selection, the pinned inventory contained 652 pairs, 100 previously
started unique pairs and 552 remaining pairs across the same 30 base tasks and
12 repositories. New combinations are not independent new repositories/tasks.

Selection uses the fixed seed cooperbench-new100-20261031, excludes every prior
run manifest regardless of outcome, and round-robins repositories and their
tasks. Candidates are hash-ordered within each task. The selected 100 identities,
excluded identities, upstream inventory hash and predecessor manifest hashes
are frozen before gates or model calls. No sample replacement after gate failure.

Model, fixed coder pool, private contexts/workspaces, asynchronous scheduling,
communication policy, submission protocol and limits remain unchanged. No new
collaboration strategy is injected based on the previous failure analysis.
The benchmark profile is clarified-v1: the two previously documented assignment
clarifications apply where relevant; hidden tests/gold remain unchanged. This
is an official-pair study with declared errata, not untouched official prompts.

Launch on the authorized server only:

    bash scripts/cooperbench/new100_pipeline.sh --authorized-new-100-paid-pairs-once

Attempt name: new100-20261031-01. Setup evidence:
outputs/setup/new100-20261031-01/. Paid output:
outputs/cooperbench/new100-20261031-01/.

The pipeline runs server scripted regressions, exact-transfer checks, all-worker
isolation probes, all 30 environment gates and all 100 selected pair gates before
payment. Gates may reuse only matching image/fingerprint evidence. It dispatches
four tasks at a time and stops new dispatch on infrastructure/capacity failures
while active tasks drain. Source/configuration must not change during paid runs.

After a blocker is repaired, continuation may start only never-started pairs,
using the complete predecessor chain with --continue-batch. The selection and
profile remain fixed. Never relaunch the full paid batch or omit failed pairs.
Keep the other agent-team project and shared resources untouched.

Completion reporting must distinguish protocol completion, joint code success,
provider/infrastructure errors and unstarted cases; include role-wise weighted
cache reuse, estimated cost, nonoverlapping account deltas (shared-key caveat),
source digests and evidence paths. No causal claim follows simply from doubling
the number of observed combinations. This batch is further exploration, not an
untouched confirmation set for hypotheses derived from overlapping features.
